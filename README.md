# Room Booker

Prudential employees (sign in with just their `@prudential.com` email) and guests book meeting rooms by the hour. Rooms are filtered by group size and video/TV needs. Employees can hold 3 upcoming bookings and guests 1. **S3** static website → **Lambda** → **DynamoDB**, fronted by CloudFront and defined in one CloudFormation template.

```
                       Browser ── POST /api/session {email | guest} ──> signed session token (HS256)
                                                                    │ HTTPS, X-Auth-Token
                       ┌─ /*      ─(HTTP + secret Referer)──>  S3 static website  (bucket policy: only CloudFront's secret)
             CloudFront (HSTS, CSP, security headers)
                       └─ /api/*  ─(SigV4 via Origin Access Control)──>  Lambda Function URL (AuthType AWS_IAM)
                                       verifies the session token (HS256, issuer, expiry) ──> DynamoDB
```

## Production decisions

| Concern | Decision |
|---|---|
| **Identity (trust-based, by request)** | Employees type an address at exactly `prudential.com`; the server checks it (look-alikes such as `prudential.com.evil.io` or subdomains are rejected) and issues a signed 12-hour session. **No password or code, so anyone who knows a colleague's address can act as them.** This was a deliberate product choice, documented as the main gap. The fix is an emailed one-time code (Cognito passwordless + SES) or SSO. Guests give a name and get a random, unguessable identity held only by their browser. Each network can start at most 5 guest sessions an hour, so clearing storage isn't a fresh quota. |
| **Quotas** | 3 upcoming bookings per employee, 1 per guest. Each owner has a record of their upcoming bookings. A booking and that record are written in **one DynamoDB transaction**, conditioned on the version that was read. Verified live: 6 parallel requests produced exactly 3 bookings. Cancelling frees a place, and past bookings stop counting. |
| **Rooms and capacity** | 6 rooms (4 to 40 seats) with features and a video/TV flag. The UI shows only rooms that seat the group (and have a screen if needed), smallest suitable room first. The server enforces it too: too many people returns `400 capacity`, and video in a room without a screen returns `400 av`. |
| **My bookings** | `/api/me` returns upcoming and the last 30 days. The email is the identity, so an employee sees their bookings on any device. Bookings are kept for 90 days (TTL). |
| **Ownership** | Bookings store the owner's id (`emp:<email>` or a random guest id). Edit and cancel are conditioned on it, so others get 403. API responses never expose owner ids or emails, only the display name and a `mine` flag. The name comes from the token, not the request body. |
| **Infrastructure as code** | [infra/template.yaml](infra/template.yaml). Change-set deploys roll back automatically on failure. `cfn-lint` runs in CI. |
| **HTTPS and headers** | HTTPS redirect, HSTS, a strict CSP (scripts, styles and connections to self only), `X-Frame-Options: DENY`, nosniff, a Referrer-Policy and a Permissions-Policy. |
| **No bypassing the edge** | The Function URL uses `AWS_IAM` auth and only this distribution can call it (OAC + `SourceArn`). The S3 website only serves requests carrying CloudFront's secret Referer. Direct calls return 403, and the smoke tests check this. |
| **CORS** | Page and API share one origin, so there's no CORS configuration for the API. |
| **Least-privilege IAM** | The Lambda role can do item operations on one table, `Query` on one index, write its own logs, and send X-Ray traces. No `Scan`. |
| **Data protection** | Point-in-time recovery, deletion protection, `DeletionPolicy: Retain` on the table, encryption at rest, TTL cleanup. |
| **Abuse controls** | 20 writes per employee per 10 minutes (atomic counter), per guest network, plus 5 new guest sessions per network per hour, plus the booking quotas. |
| **Input validation** | Room and slot allow-lists, real dates within the booking window, length limits, control characters stripped, a 2 KB body cap. The UI renders with `textContent` only. |
| **Observability** | JSON request logs (status and latency; never names, emails, titles or tokens), X-Ray, alarms on Lambda errors, throttles and CloudFront 5xx rate, sent to SNS. |
| **UI** | Apple-style design with an animated boardroom-with-sea-view scene (day and night SVG, generated by [tools/make_scene.py](tools/make_scene.py)): system font (SF on Apple devices), frosted-glass navbar, large titles, Calendar-style day strip, a booking-quota ring, an iOS-style bottom sheet on phones and a centered sheet on desktop, automatic light/dark, reduced-motion support. |

## Branding
The page shows a "Prudential" wordmark. To use the official logo, put it at `frontend/assets/logo.svg` and run `deploy.py`; it replaces the wordmark automatically. The footer says it's an internal demo, not an official Prudential system.

## Deploy / operate
```powershell
python -m venv .venv; .\.venv\Scripts\pip install -r requirements-dev.txt
aws login                                                   # or aws configure
.\.venv\Scripts\python deploy.py                            # create/update, then smoke tests
.\.venv\Scripts\python deploy.py --alert-email you@example.com
.\.venv\Scripts\python teardown.py --yes [--delete-data]
.\.venv\Scripts\pytest tests                                # 55 tests (moto-mocked DynamoDB)
```

## Known limits and next steps
- **Prove the email.** Sign-in is trust-based. Next step: email a one-time code (needs SES production access), or federate with the corporate IdP (Entra ID / Okta) for real SSO.
- **No WAF.** Rate limits are in the app to avoid a fixed monthly cost. In production, add AWS WAF rate-based rules at CloudFront.
- **Concurrency.** The account limit is 10, so no reserved concurrency is set. Raise the quota and set `ReservedConcurrency`.
- **Domain and environments.** Add a custom domain (ACM + Route 53), a stack per stage, and CI deploys via GitHub OIDC.
